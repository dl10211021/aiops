## 2. 产品定位

OpsCore AIOps 企业版面向数据中心、私有云、混合云和企业 IT 运维场景，提供资产统一接入、AI 会话式运维、协议化巡检、安全动作管控、审批审计、知识沉淀、告警联动和可视化运营能力。

产品不是单纯监控采集平台，而是“AI 驱动的运维控制与执行平台”。它需要连接大量异构系统，并在安全策略约束下让 AI 能够查询、诊断、配置、巡检和生成运维报告。

## 3. 建设目标

1. 建立企业级资产中心，统一管理主机、数据库、中间件、网络、虚拟化、存储、监控、安全和业务平台资产。
2. 建立协议驱动的连接与工具体系，让每类资产都有明确的连接参数、认证方式、可用工具和巡检模板。
3. 提供中文为主、企业化、低学习成本的 AI 运维会话界面。
4. 支持只读巡检、读写操作、审批操作、禁止操作和网络边界管控。
5. 支持快捷命令、附件上传、交互确认、工具执行轨迹、阶段性报告和会话编辑。
6. 支持企业级审批、审计、告警、巡检任务、知识库和技能市场。
7. 支持多模型、多供应商和企业内部模型网关接入。
8. 支持私有化部署、备份恢复、权限隔离和生产发布门禁。

## 5. 使用场景

### 5.1 资产接入与验证

用户在资产中心选择资产类型、协议和凭据，系统完成连接测试、协议原生探测、工具目录生成和基础只读巡检。

典型资产包括：

- Linux、Windows、Unix、国产操作系统。
- Oracle、MySQL、PostgreSQL、SQL Server、MongoDB、Redis、Elasticsearch 等数据库与缓存。
- Kubernetes、Docker、OpenShift、容器运行时。
- Nginx、Tomcat、Kafka、RabbitMQ、RocketMQ、ZooKeeper、Nacos、Consul、Harbor 等中间件。
- 交换机、路由器、防火墙、WAF、负载均衡、VPN。
- VMware、vCenter、ESXi、Proxmox、OpenStack、ZStack 等虚拟化平台。
- S3、MinIO、OSS、COS、OBS、Ceph、NFS、NAS、SAN、HDFS 等存储。
- Prometheus、Grafana、Zabbix、Alertmanager、Loki、VictoriaMetrics、ManageEngine 等监控平台。
- Redfish、iLO、iDRAC、IPMI、SNMP 设备等带外管理。
- HTTP API、REST API、企业内部平台、CI/CD、安全平台和业务系统。

### 5.2 AI 会话式运维

用户打开某个资产会话后，AI 自动获得当前资产上下文、协议工具、安全边界和快捷命令。用户可通过自然语言或快捷命令发起巡检、配置查看、日志分析、风险排查和变更操作。

AI 不应要求用户重复提供账号密码。工具调用必须使用资产中心托管凭据。

### 5.3 安全策略与审批

系统基于动作策略判断 AI 的工具调用：

- 允许执行：只读查询或企业已明确允许的动作。
- 需要审批：可能改变状态但允许人工确认的动作。
- 禁止执行：危险、不可逆、超出边界或违反合规的动作。

用户应能在拦截提示中快速把某类动作配置为允许、审批或禁止，不需要直接理解复杂正则表达式。

### 5.4 巡检与报告

用户可对单资产、资产组、标签、分类、协议或全局范围发起巡检。巡检结果生成结构化报告，支持查看、导出、审计和后续会话追问。

### 5.5 告警联动与 Webhook

外部告警平台可通过 Webhook 接入 OpsCore。告警可关联资产、拉起 AI 会话、触发只读分析、生成处理建议，并可把会话画像或报告发送到指定 Webhook。

### 5.6 知识沉淀与技能扩展

用户可上传文档、日志、表格、图片等材料，系统解析后进入会话上下文或知识库。技能市场提供可安装、可编辑、可验证和可回滚的运维技能。

## 7. 功能需求

### 7.1 运维总览

#### 7.1.1 资产概览

系统应展示资产总数、在线资产、异常资产、按分类统计、按协议统计、工具覆盖率和近 24 小时巡检结果。

验收标准：

- 页面首屏展示资产、告警、巡检和风险核心指标。
- 不展示任何明文密码、Token、私钥、连接串敏感字段。
- 数据来自后端聚合接口，不在前端硬编码统计口径。

#### 7.1.2 数据中心趋势

运维总览与趋势大屏应合并设计，避免重复页面。普通控制台展示精简趋势，大屏模式展示全屏可视化。

验收标准：

- 支持告警趋势、巡检成功率趋势、资产增长趋势和风险等级趋势。
- 支持按时间范围筛选。
- 支持大屏展示模式。

### 7.2 资产中心

#### 7.2.1 资产目录

系统应提供后端驱动的资产目录。资产类别、协议、默认端口、认证字段、连接参数、工具集和巡检模板应从统一目录生成。

资产分类建议：

| 一级分类 | 二级示例 |
| --- | --- |
| 操作系统与主机 | Linux、Windows、Unix、国产 OS、裸金属 |
| 数据库与缓存 | Oracle、MySQL、PostgreSQL、SQL Server、Redis、MongoDB、Elasticsearch |
| 容器与云原生 | Kubernetes、OpenShift、Docker、Containerd、Harbor |
| 中间件 | Nginx、Tomcat、Kafka、RabbitMQ、RocketMQ、ZooKeeper、Nacos、Consul |
| 网络与安全 | Switch、Router、Firewall、WAF、VPN、F5、A10 |
| 虚拟化与私有云 | VMware、vCenter、ESXi、Proxmox、OpenStack、ZStack |
| 存储与备份 | S3、MinIO、OSS、COS、OBS、Ceph、NFS、NAS、SAN、HDFS |
| 监控与告警 | Prometheus、Grafana、Zabbix、Alertmanager、Loki、ManageEngine |
| 带外与硬件 | Redfish、iLO、iDRAC、IPMI、SNMP Device |
| API 与业务平台 | HTTP API、REST API、CMDB、ITSM、CI/CD、安全平台 |

验收标准：

- 资产类别与协议联动。
- 数据库资产不能默认显示 HTTP/REST，除非该数据库类型确实走 API 管理通道。
- Oracle 支持 SID、Service Name、TNS Alias，并支持 Thick Client 配置变量。
- Windows 支持 WinRM，Linux 支持 SSH。
- S3/对象存储支持 endpoint、region、bucket、access key、secret key 等字段。

#### 7.2.2 连接凭证

系统应支持账号密码、私钥、Token、API Key、证书、连接串和平台专用凭据。

验收标准：

- 凭据加密存储。
- 前端编辑时敏感字段脱敏展示。
- 保存 `********` 不覆盖原密钥。
- 连接失败应区分密码错误、网络失败、协议失败、驱动缺失、内部错误。

#### 7.2.3 资产新增与刷新

验收标准：

- 添加资产弹窗不因鼠标移出而关闭。
- 保存成功后资产列表自动刷新并定位新资产。
- 连接失败时给出明确中文错误。
- 支持“测试连接”“只读巡检”“连接并打开会话”三种动作。

### 7.3 协议工具体系

每个资产应映射到明确协议和工具集。

| 协议 | 典型资产 | 能力 |
| --- | --- | --- |
| SSH | Linux、网络设备、中间件主机、存储主机 | 命令执行、日志读取、配置查看、服务状态 |
| WinRM | Windows Server | PowerShell、服务、事件日志、性能指标 |
| SQL/Oracle/MySQL 等 | 数据库 | SQL 查询、实例状态、参数查看、读写执行 |
| SNMP | 网络、存储、带外设备 | OID 查询、接口状态、系统信息 |
| HTTP API/REST | 监控平台、业务平台、云平台 | API 查询、配置读取、有限变更 |
| Kubernetes API | K8s、OpenShift | 资源查询、事件、Pod、节点、命名空间 |
| S3 API | MinIO、S3、OSS、COS、OBS | Bucket、对象、权限和容量信息 |
| Redfish/IPMI | 服务器带外 | 硬件、电源、传感器、事件 |

验收标准：

- 工具目录由后端生成。
- 聊天、巡检、定时任务和后台任务使用同一套工具策略。
- 读写模式下数据库非 SELECT 语句可执行，但必须经过动作策略和审批规则。

### 7.4 AI 会话

#### 7.4.1 会话主界面

会话界面应参考当前项目已有布局，重点优化企业化细节。

需求：

- 顶部显示资产名称、协议、账号、只读/读写状态、巡检状态、技能和更多操作。
- 模型选择和思考模式应靠近输入区或会话控制区，避免占用过大顶部空间。
- 输出字体适合中文运维阅读，默认不应过小。
- AI 消息宽度应充分利用聊天区域，不应只挤在左半边。
- 工具轨迹、审批提示、交互确认应固定或浮出到可见区域，不应只出现在流输出最底部。

验收标准：

- 不同会话输入框内容互不串联。
- 页面刷新后，正在执行任务不应静默中断；至少提示任务状态并支持恢复查看。
- 支持删除某段会话消息。
- 支持编辑某段输出消息文字，并保留审计标记。

#### 7.4.2 输入区

需求：

- 输入框随内容自动扩张。
- 发送按钮位置应避开输入法候选区，避免误触。
- 移除无必要的上一页/下一页按钮。
- 支持图片、Excel、CSV、TXT、Word、PDF、日志等附件上传。
- 附件上传后先解析为当前消息的一部分，用户可继续补充文字，一次性发送。

验收标准：

- 单次消息支持多个附件，受大小和数量限制。
- 解析失败展示明确原因。
- 图片在模型支持视觉时可作为视觉输入，否则以图片摘要参与上下文。

#### 7.4.3 快捷命令

需求：

- 快捷命令来自后端会话命令接口。
- 支持内置模板、自定义命令、按资产类型、按协议、按单资产生效。
- 支持排序编辑：进入排序模式后，用户按顺序点击，第一个保存为 1，第二个保存为 2，依次类推。
- 内置模板点击卡片为查看，编辑按钮为编辑。
- 已覆盖内置模板支持恢复默认。
- 快捷栏显示当前会话可用命令，固定项排前，其余命令继续展示或横向滚动。

验收标准：

- 输入 `/` 展示完整斜杠菜单。
- 自定义命令保存后立即刷新。
- 排序保存后快捷栏和菜单顺序一致。

#### 7.4.4 交互模式

AI 在需要用户选择、输入密码、确认风险、选择处理方案时，应通过结构化交互卡片请求用户反馈。

验收标准：

- 支持文本输入、单选、多选、确认/取消。
- 交互卡片在当前视图可见区域提示。
- 超时后给出可恢复提示。

#### 7.4.5 会话画像

系统应支持基于多维度巡检结果生成资产画像。

画像内容包括：

- 资产类型推断。
- 运行角色推断，如数据库服务器、Web 服务器、跳板机、K8s 节点、存储节点。
- 关键服务和端口。
- 风险重点。
- 后续排查建议。
- 支撑证据。

验收标准：

- 画像在会话 UI 上显示为卡片或面板。
- 画像写入会话记忆，可供后续分析使用。
- 支持发送到指定 Webhook。

### 7.5 安全策略

#### 7.5.1 动作策略

企业版安全策略以“动作策略”为主配置入口。

动作策略应覆盖：

- 读操作。
- 写操作。
- 配置变更。
- 服务启停。
- 文件变更。
- 数据库 DDL/DML。
- 网络探测。
- 存储删除。
- 虚拟化变更。
- K8s 资源变更。
- Webhook 发送。

决策类型：

- 允许执行。
- 需要审批。
- 禁止执行。

验收标准：

- 普通用户不需要写正则。
- 被拦截命令可一键生成动作策略。
- 历史高级审批/禁止规则不得覆盖动作策略的可见优先级。

#### 7.5.2 只读模式

只读模式默认应允许真正的读取类命令。

Linux 只读示例：

- `free -m`
- `df -hT`
- `lscpu`
- `journalctl -p err`
- `crontab -l`
- `systemctl status`
- `systemctl list-units --state=failed`
- `last reboot`
- `cat /etc/fstab`
- `mount` 的读取当前挂载状态

验收标准：

- 读取日志、系统服务状态、资源信息不应被默认拦截。
- 如果某命令被误拦截，用户可从拦截卡片快速配置为允许读取。

#### 7.5.3 网络边界

系统应支持网络管控，让 AI 只在指定地址、网段或资产范围内进行活动。

需求：

- 配置允许活动的 IP、CIDR、域名、资产组。
- 未知目标可设置为只读、审批或禁止。
- HTTP GET、Ping、DNS、端口探测等都应纳入边界判断。
- 支持按会话、资产组或全局配置。

验收标准：

- AI 不得绕过网络边界访问未授权目标。
- 命中边界策略时显示明确中文原因。

#### 7.5.4 审批与审计

需求：

- 高危动作进入审批队列。
- 审批记录包含操作人、时间、动作、参数、目标、理由、结果。
- 支持批准、拒绝、超时、批量处理。
- 一键全部批准需二次确认并记录原因。

验收标准：

- 聊天、定时任务、Heartbeat、Webhook、后台任务、子 Agent 均走统一策略和审计。
- 审批结果可追溯。

### 7.6 巡检任务

需求：

- 支持单资产巡检。
- 支持按资产组、标签、分类、协议、资产类型批量巡检。
- 支持定时任务。
- 支持任务暂停、恢复、删除、立即执行。
- 支持运行记录、失败原因、报告导出。

验收标准：

- 定时任务不应把所有技能无差别挂入上下文。
- 巡检执行使用协议原生工具。
- 任务结果可在资产详情和巡检页查看。

### 7.7 告警中心

需求：

- 支持外部 Webhook 接入。
- 支持告警标准化字段：来源、资产、严重级别、标题、内容、状态、时间、标签。
- 支持认领、关闭、备注、关联会话。
- 支持根据告警触发 AI 只读分析。

验收标准：

- 外部告警文本不得绕过安全策略诱导工具调用。
- 告警触发的后台会话必须进入统一审批和审计链路。

### 7.8 知识库

需求：

- 技能市场和知识库应独立页面。
- 支持上传 TXT、Markdown、PDF、Word、Excel、CSV、日志。
- 支持解析、索引、检索、引用展示。
- 支持按知识库、资产、团队、权限隔离。

验收标准：

- 前后端支持的文件类型一致。
- 上传失败给出明确原因。
- 引用内容可追溯到来源文档。

### 7.9 技能市场

需求：

- 支持技能安装、启用、停用、编辑、验证、版本和回滚。
- 支持内置技能与自定义技能区分。
- 支持按资产类型推荐技能。
- 支持安全扫描和审批后生效。

验收标准：

- 自我进化类技能必须经过校验、版本、回滚和安全审批。
- 技能变更默认延迟生效，必要时允许立即生效。

### 7.10 模型配置

需求：

- 支持 OpenAI 兼容接口、企业模型网关、本地模型、Claude、Gemini、DeepSeek、Qwen 等模型供应商。
- 支持默认模型、会话模型、思考模式配置。
- 支持连通性测试。
- 支持模型能力标记，如文本、视觉、工具调用、长上下文。

验收标准：

- 模型配置错误应明确提示供应商、URL、鉴权或模型不可用。
- UI 中文为主，布局企业化。

### 7.11 通知与 Webhook

需求：

- 支持把会话画像、巡检报告、告警分析、审批结果发送到指定 Webhook。
- 支持企业微信、钉钉、邮件、自定义 HTTP。
- 支持敏感字段脱敏。

验收标准：

- Webhook 地址需经过安全校验。
- 默认禁止发送到未授权内网或外网地址，除非策略允许。

## 8. 非功能需求

### 8.1 安全

- 凭据加密存储。
- 敏感信息脱敏展示。
- 前后端统一错误语义。
- 所有工具调用经过策略判断。
- 支持审计日志导出。
- 支持网络边界和目标范围控制。

### 8.2 可用性

- 核心页面中文为主。
- 企业控制台风格，信息密度适中。
- 危险操作必须清晰提示。
- 普通用户无需理解正则即可配置常用安全策略。

### 8.3 性能

- 流式输出不应因长 Markdown 卡顿。
- 大列表使用分页、筛选或虚拟滚动。
- Dashboard 聚合接口应避免前端 N+1 请求。

### 8.4 可扩展性

- 新资产类型应通过后端资产目录扩展。
- 新协议应通过连接管理器和工具注册扩展。
- 新工具应具备 schema、权限、执行器、测试和审计元数据。

### 8.5 可部署性

- 支持 Windows 开发环境。
- 支持 Linux 生产部署。
- 支持 Docker、systemd、离线依赖部署。
- Oracle Instant Client 等外部驱动通过环境变量配置路径。

### 8.6 可维护性

- 前端大组件应逐步拆分。
- API 错误语义统一。
- 安全策略和动作目录应有测试覆盖。
- Hermes 源码仅作为参考，不参与常规提交。

## 13. 风险与约束

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 资产类型过多导致目录漂移 | 连接参数错误、工具错配 | 后端统一资产目录，前端只消费接口 |
| 安全策略过复杂 | 用户不会配置，误拦截 | 以动作策略为主，隐藏高级规则 |
| AI 工具调用不可控 | 误操作生产系统 | 统一 Policy + Approval + Audit |
| 数据库驱动依赖复杂 | Oracle 等连接失败 | 提供驱动安装说明和环境变量 |
| 前端组件过大 | 后续维护困难 | 按页面逐步拆分组件和 hook |
| 后台任务绕过审批 | 安全风险 | 后台任务统一走安全策略 |
| 知识和技能污染上下文 | AI 输出不稳定 | 按需挂载，默认延迟生效 |

## 14. 不在本版本范围

- 替代完整监控采集平台。
- 直接替代 CMDB、ITSM、堡垒机。
- 默认开放无边界网络扫描。
- 默认允许 AI 绕过审批执行高危变更。
- 直接全量迁移 Hermes 架构。

## 15. 附录：企业版核心原则

1. 资产是中心，协议是通道，工具是能力，策略是边界。
2. AI 可以执行，但必须可控、可审计、可回滚。
3. 普通用户看到的是动作和影响，不是正则和内部规则。
4. 数据中心资产类型必须准确，不用监控采集思维替代运维执行思维。
5. 前端以中文企业控制台为主，减少炫技，提升效率。
6. 后端是能力和安全边界的唯一可信来源。
7. 所有后台自治能力都必须进入统一策略、审批和审计链路。
